# yamem

Простой файловый навык памяти проекта для AI-агентов.

Навык хранит рабочий контекст проекта в markdown-файлах внутри `.agents/memory/` и подходит для агентов, которые умеют:

- читать инструкции из `SKILL.md`;
- работать с файлами проекта;
- при необходимости выполнять команды `git`.

Навык не требует базы данных, внешних сервисов или обязательных скриптов. Он рассчитан на простую файловую память проекта с допустимой, но не строгой согласованностью.

## Что хранится в памяти

В `.agents/memory/` могут храниться:

- факты и устойчивый контекст проекта;
- краткий дневник содержательной работы;
- активные, отложенные и завершённые задачи;
- тематические заметки, рецепты и уроки;
- артефакты отдельных задач.

Навык не предназначен для хранения секретов, персональных данных и чувствительной инфраструктурной информации.

## Как это работает

При первом сообщении в чате агент:

1. читает конфиг памяти, если он есть;
2. пытается мягко синхронизировать локальную память и подключённые shared-базы, если это настроено;
3. читает основную память, backlog и недавний дневник;
4. кратко сообщает статус preflight;
5. при необходимости предлагает оптимизацию памяти, но не изменяет файлы без подтверждения пользователя.

Во время содержательной работы агент может:

- добавлять записи в дневник;
- обновлять backlog и archive;
- добавлять устойчивые факты в `MEMORY.md`;
- сохранять тематические знания в `topics/`;
- создавать папки задач с артефактами в `tasks/`.

Память обновляется только если в ходе работы появился устойчивый полезный результат. Короткие ознакомительные ответы и пустые действия не записываются.

## Shared-память

В `.agents/memory/shared/` можно подключать общие базы знаний, например `admin-recipes`, `accounting`, `1c-dev`.

В shared-память попадают только:

- обезличенные рецепты;
- переиспользуемые инструкции;
- устойчивые уроки, полезные вне текущего проекта.

В shared нельзя записывать:

- секреты и токены;
- IP-адреса, хосты, логины;
- названия клиентов и другие идентификаторы;
- внутренние URL, домены и чувствительный бизнес-контекст.

## Установка

Размести навык в каталоге `.agents/skills/yamem/`.

Это можно сделать копированием, симлинком или submodule.

Пример подключения как submodule:

```bash
git submodule add https://github.com/rsyuzyov/yamem .agents/skills/yamem
git commit -m "feat: add yamem skill"
```

Обновление:

```bash
git submodule update --remote .agents/skills/yamem
git commit -m "chore: update yamem"
```

## Подключение к агентам

Если агент читает навыки не из `.agents/skills/`, а из своей папки, создай ссылку на `.agents/skills/yamem/`.

Ниже приведены примеры для shell, совместимого с Unix:

| Агент       | Папка навыков     | Команда                                                                             |
| ----------- | ----------------- | ----------------------------------------------------------------------------------- |
| Antigravity | `.agents/skills/` | Ничего не нужно                                                                     |
| Claude Code | `.claude/skills/` | `mkdir -p .claude/skills && ln -s ../../.agents/skills/yamem .claude/skills/yamem` |
| Codex       | `.codex/skills/`  | `mkdir -p .codex/skills && ln -s ../../.agents/skills/yamem .codex/skills/yamem`   |
| Cursor      | `.cursor/skills/` | `mkdir -p .cursor/skills && ln -s ../../.agents/skills/yamem .cursor/skills/yamem` |

Для Windows или других агентов используй эквивалентную ссылку, копирование каталога или явное указание пути в системном промпте.

## Системный промпт

При желании можно добавить в системный промпт:

```text
Если в проекте есть .agents/skills/yamem/SKILL.md, прочитай его в начале работы и следуй правилам разделов «При старте», «При работе над задачей» и «Перед ответом».
```

## Согласованность

Навык рассчитан на best-effort синхронизацию и eventual consistency.

Если `git pull`, commit или push недоступны из-за конфликта, отсутствия remote, отсутствия сети или грязного дерева, агент должен кратко сообщить причину и продолжить основную работу без блокировки.

## Безопасность

Используйте `gitleaks` или аналогичную проверку.

Правила:

- не хранить в памяти пароли, токены, ключи и секреты;
- не хранить персональные данные и чувствительные данные клиентов;
- секреты хранить во внешнем хранилище или в `.env`, если это допустимо политикой проекта;
- в памяти хранить только имя переменной, описание секрета или указание, где его искать.
