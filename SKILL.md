# Память проекта

## Структура

```
.agents/memory/
├── MEMORY.md       — факты, контекст проекта, уроки
├── diary/          — ежедневный лог работ
│   └── YYYY-MM-DD.md
├── backlog.md      — активные задачи ([ ], [/])
├── archive.md      — завершённые задачи ([x])
├── topics/         — тематические знания (читать по необходимости)
├── shared/         — общие базы знаний (git submodules, опционально, может быть несколько)
│   └── <имя-базы>/
│       └── topics/
└── tasks/          — папки задач с артефактами
    └── YYYY-MM-DD-тема/
        ├── plan.md
        ├── report.md
        └── ...
```

## Правила

### При старте

- Если это git-репозиторий, рабочее дерево чистое и для текущей ветки настроен upstream/remote для pull — попробуй выполнить `git pull --rebase` для синхронизации памяти
- Если `git pull --rebase` не выполнен, не нужен или неуместен — не останавливай работу
- Если каталога `.agents/memory/` нет — создай всю структуру:
  - `MEMORY.md` (`# Memory Index`)
  - `diary/` (пустой каталог)
  - `backlog.md` (`# Бэклог` + секция `## Активные` + ссылка на archive.md)
  - `archive.md` (`# Архив`)
  - `topics/` (пустой каталог)
- Прочитай `MEMORY.md`, `backlog.md` и файлы дневника за последние 7 дней (`diary/`)
- В первом содержательном ответе кратко укажи статус preflight: `memory synced` или `memory not synced`
- Общие базы знаний (`shared/`):
  - Если есть submodule-ы в `shared/` — обнови: `git submodule update --remote`
  - Если `shared/` пуст или нет — уведоми пользователя: "Общие базы знаний не подключены. Подключить: `git submodule add <url> .agents/memory/shared/<имя>`"
  - Не уведомлять, если в `MEMORY.md` есть фраза "Не уведомлять об общих базах"
  - Используй `shared/*/topics/` как дополнительный источник знаний (читай по необходимости)

### При работе над задачей

- Создай папку задачи: `tasks/YYYY-MM-DD-тема/`
- Перед выполнением задачи попробуй найти папку похожей задачи и изучи опыт

### Перед финальным ответом

- Если в ходе работы появились новые факты, уроки, задачи или артефакты — обнови память проекта
- Если работа была только ознакомительной и сохранять нечего — память можно не обновлять
- Добавь запись в `diary/YYYY-MM-DD.md` (создай файл дня, если нет)
- Перенеси выполненные задачи из `backlog.md` в `archive.md`
- Добавь новые задачи в `backlog.md`
- Общие факты и уроки → `MEMORY.md`
- Тематические знания → соответствующий файл `topics/`. Если были грабли, нестандартные решения или новая тема — создай/дополни топик автоматически, не спрашивая
- Если есть `shared/` — обезличенный рецепт в подходящую базу `shared/<имя>/topics/` (без IP, хостов, учёток — только плейсхолдеры)
- `git add .agents/memory/ && git commit -m "memory: краткое описание" && git push`

### Безопасность

- Не храни пароли и секреты в файлах памяти. Секреты — в `.env` (gitignored), в памяти пиши только имя переменной

### Поиск

- Если не уверен, где нужная информация — используй grep по `.agents/memory/`

### Команды пользователя

| Фраза пользователя                                                 | Действие агента                   |
| ------------------------------------------------------------------ | --------------------------------- |
| "что в отложках", "что в бэклоге", "покажи бэклог", "какие задачи" | Прочитай `backlog.md`             |
| "что делали сегодня / вчера / на прошлой неделе"                   | Прочитай нужные файлы из `diary/` |

### Оптимизация памяти

Единый механизм обслуживания: уборка и глубокий анализ содержания.

**Триггер:**

- По команде пользователя: "Оптимизируй память"
- Автоматически при старте, если `Последняя оптимизация: YYYY-MM-DD` в `MEMORY.md` старше 7 дней (или метки нет)

#### Фаза 1 — Анализ (без изменений в файлах)

**Дневник (`diary/`):**

- Найти файлы старше 30 дней (кандидаты на удаление — ключевые факты к этому моменту уже в `MEMORY.md` и `topics/`)

**Архив (`archive.md`):**

- При >50 записей — предложить вынести старые в `archive/YYYY-MM.md`, оставить последние 30 дней

**Задачи (`tasks/`):**

- Папки старше 30 дней — кандидаты на уборку:
  1. Отметить ценные инструкции (guide, checklist) для переноса в `topics/` (обезличенное → `shared/`)
  2. Проверить что ключевые факты отчётов есть в дневнике/`MEMORY.md`

**Топики (`topics/`) — дедупликация:**

- Найти пересечения контента между `topics/*.md` и `shared/*/topics/*.md`
- Отметить дубли для удаления из локального топика (оставить только специфику проекта + ссылку на shared)

**Топики (`topics/`) — перенос в shared:**

- Найти обезличенные рецепты в `topics/`, которых нет в `shared/` — кандидаты на перенос

**Бэклог (`backlog.md`):**

- Задачи без движения >30 дней — кандидаты на архивацию

**MEMORY.md:**

- Найти мёртвые ссылки на удалённые файлы
- Отметить факты, которые выглядят устаревшими

#### Фаза 2 — Отчёт

Показать пользователю сводку предложений:

- Что удалить (дневник, задачи, дубли)
- Что перенести в `shared/`
- Что архивировать (бэклог)
- Что уточнить (устаревшие факты — вопросы пользователю)

**Ждать одобрения.** Не изменять файлы до подтверждения.

#### Фаза 3 — Выполнение (после одобрения)

- Удалить одобренные файлы дневника и папки задач
- Удалить дубли из локальных топиков, оставить специфику + ссылку на shared
- Перенести рецепты в `shared/<имя>/topics/`:
  - `cd <shared-submodule> && git add . && git commit -m "recipe: описание" && git push`
- Архивировать протухший бэклог → `archive.md`
- Удалить мёртвые ссылки из `MEMORY.md`
- Обновить `Последняя оптимизация: YYYY-MM-DD` в `MEMORY.md`
- Коммит основного репо: `memory: optimize YYYY-MM-DD`

## Примеры

### Запись в дневник (diary/YYYY-MM-DD.md)

```markdown
# 2026-03-21

### Краткое название задачи

- Что сделано
- Грабля: проблема и решение
- Задача: [tasks/2026-03-21-тема/](tasks/2026-03-21-тема/)
```

### Запись в бэклог (backlog.md)

```markdown
## Активные

- [ ] Задача, которую нужно сделать
- [/] Задача в работе

Завершённые задачи → [archive.md](archive.md)
```

### Запись в архив (archive.md)

```markdown
# Архив

- [x] 2026-03-21: Что было сделано
```

### Структура папки задачи

```
tasks/2026-03-21-pgpro-upgrade/
├── plan.md          — план работ (опционально)
├── report.md        — отчёт о выполнении
├── guide.md         — инструкция (если создавалась)
└── checklist.md     — чек-лист (если нужен)
```

### Запись в топик

Файл `topics/имя-темы.md`:

```markdown
# Название темы

## Подтема

- Факт или урок
- ⚠️ Грабля: описание и решение
```
