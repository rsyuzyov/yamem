# Память проекта (yamem)

Раскладка делит память не по признаку «наше / общее», а по тому, едет ли знание
с проектом:

- **журнал проекта** — привязан к этому проекту и никуда не отчуждается;
- **банки** (`banks/`) — знание, которое можно отдать и переиспользовать где угодно.

```text
.agents/memory/
├── yamem.config.yaml     # какие банки подключены
├── MEMORY.md             # устойчивые факты, ограничения и правила; читается каждую сессию
├── tasks/<YYYY-MM>/<slug>/   # задачи: task.md (что сделать + критерий), journal.md (ход), артефакты
├── diary/<YYYY-MM>/      # что происходило по дням, по файлу на сессию
├── backlog.md            # ⚙️ генерируемое представление открытых задач — руками не править
├── archive.md            # ⚙️ генерируемое представление завершённых — руками не править
└── banks/
    └── local/            # свои топики: привязанное к месту, проекту, клиенту
```

Банк со своими топиками зовётся `local` — одинаково в любой установке. Вопроса «класть
в свою память или в общую» нет: есть routing «в какой банк».

⚠️ **Одноимённые топики в разных банках — не дубль, а пара «универсальное + дельта»:
читать оба.**

## Представления

`backlog.md` и `archive.md` собираются из фронтматтеров `tasks/*/*/task.md`, список топиков
в README банка — из фронтматтеров топиков:

```bash
python scripts/gen-backlog.py      --memory <путь к .agents/memory> --apply
python scripts/gen-topics-index.py --memory <путь к .agents/memory> --apply
```

Правка руками теряется при следующей сборке. Расхождение чинится в самой задаче или топике,
после чего представление пересобирается — обязательно **после `git fetch && git rebase @{u}`**, иначе
своей сборкой откатишь задачи соседней сессии.
